# Working on The shelf

Read `README.md` and these continuation notes before changes. The README covers setup and the source map; this file records implementation constraints. This repository is self-contained for running and editing; no access to the original conversation, private design writing or parent workspace handoffs is required. This is a standalone static website: the 3D app is at the repository root, the preserved CSS compatibility view and shared card data/images are in `compatibility/`, and Three.js is in `vendor/three/`. Keep URLs relative so GitHub Pages repository prefixes work. Keep the README concise and technical; editorial design writing lives outside the repository and is not a prerequisite for development.

Use Node.js 20 or newer. `node server.mjs` serves the root on port 4318. Set `BASE_PATH=/the-shelf/` to test a nested Pages-style URL. `node checks/run-checks.mjs` runs the existing checks; no dependency installation or build is needed. `npm start` and `npm test` are equivalent shortcuts when npm is available.

Version 1.0.0 is the initial release baseline, with a fresh single-commit main history. Continue subsequent work with normal commits unless the user explicitly requests another history rewrite. Keep local history backups, editorial drafts and private-preview state out of the repository.

Compatibility mode lives in `compatibility/`, with `index.html`, `compatibility.css`, `compatibility.js`, the shared `cards.js` catalogue and image assets. General settings provides a native link to it; its bottom link returns to the main 3D app. The old `shelf/` directory/address is retired with no redirect, as requested. Keep module imports, scan preparation paths, offline closure, error/noscript links and the private-preview allowlist aligned with this structure. The compatibility page itself remains outside the main 3D offline guarantee.

Ground movement is an experimental Settings option, off on first visit and saved thereafter. Preserve ordinary card selection when it is disabled, and preserve inspection framing when turning it off. Keep reduced-motion and on-demand idle rendering behaviour. Open cards support one-finger rotation, two-finger pinch/pan and a continuous return to one-finger rotation; preserve pickup guards and cancellation cleanup.

The bottom-left eye control hides regular interface elements for the current visit, retaining the eye, leaf, gear and Put back. Keep masked controls inert and invisible, including the normally persistent night bulb, without removing layout used for inspection framing. Hiding ends held gestures but preserves card/time journeys. Put back must focus the eye rather than an inert collection button while hidden. Gear can deliberately reopen Settings; a fresh visit starts visible, and load errors restore the interface. Do not persist this mode as a graphics preference.

With the interface hidden and a card selected, a second vector button beside the eye toggles Front/Inside for folded cards and Front/Back for postcard 07. It is disabled during pickup, disappears on return/show, and reuses the normal 650 ms view transition with Advanced timing and reduced motion. Repeated clicks reverse from the displayed pose using the current destination to choose the next action. Preserve its dynamic accessible label and icon, both fold axes, and pointer interruption cleanup.

Reserve the actual persistent-tool rectangles and fit the rotated paper envelope, including fold depth. Resize retains the expanded framing; Show animates back to normal inspection framing. Run `checks/motion-check.mjs` and the full 14-suite runner when changing this integration.

Keep `server.mjs` loopback-only and `RUNTIME_ONLY=1` for Tailscale, with the exact app/compatibility allowlist. Automatic quality uses a 30 FPS budget. Begin passively from saved preferences or 1×/Balanced, without a startup sweep or forced idle rendering.
